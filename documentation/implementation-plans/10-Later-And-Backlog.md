## Purpose

Preserve accepted later direction without over-planning it, and record backlog-only ideas without further detail.

## Later: Independent Mobile Experience

### Current Architectural Preparation

- Keep content, graph, AI context, destinations, and discovery semantics independent from desktop geometry.
- Use semantic checkpoints rather than camera matrices.
- Keep project demo logic separable from desktop presentation.
- Avoid assuming hover in shared domain models.
- Treat desktop aesthetic art packets as evidence of portfolio laws and content hierarchy, not as mobile layout specifications.

### Later Exploration

- Design mobile as a tactile field guide using stacking, folding, sliding, and haptics.
- Reuse knowledge and discovery state without requiring desktop interaction parity.
- Author independent mobile art packets for Home, museum, one flagship, AI, and reading before mobile production styling.
- Run a separate mobile design and usability phase after desktop core stability.

No detailed screen plan is required now.

## Later And Closely Co-Designed: Musical Identity

### Current Architectural Preparation

- Centralize sound settings and audio ownership.
- Expose event hooks for meaningful interactions.
- Support visual rhythm when sound is off.
- Avoid committing to a note count or motif in code.

### Later Collaboration

- Work directly with Mark on emotional purpose, motif, instrumentation, frequency, project variations, and taste.

Do not plan the composition in further detail now.

## Later: Ambient Multi-Visitor Presence

### Current Architectural Preparation

- Keep visitor discovery state separate from any presence client.
- Reserve optional presence visual hooks in shared environments.
- Document privacy constraints.

### Later Narrow Prototype

- Anonymous distant light or ripple only.
- No chat, identity, typed content, or detailed cursor tracking.
- Real activity only, with a clear opt-out.

Do not choose a real-time provider or protocol until the single-person experience is stable.

## Later: Shared Exploration

### Possible Sequence

1. Restore a safe shared destination state from a link.
2. Allow Mark and a guest to view the same exhibit state.
3. Evaluate synchronized navigation.
4. Consider independent guest inspection within shared context.

Do not detail synchronization architecture now.

## Deferred And Unresolved: Broader Graph View

First validate semantic lighting, About connections, AI cards, and the skill evidence prototype. A large public graph view should only be planned if those interactions prove that visitors benefit from seeing the graph more directly.

## Backlog Only

- Anti-Resume deep layer: revisit after flagship project stories and living state are mature.

## Promotion Rules

An item moves from Later or Backlog into active planning only when:

- Mark confirms priority.
- Required earlier systems are stable.
- The visitor value is clearer than the implementation novelty.
- A specific product question can be answered by a bounded prototype.
